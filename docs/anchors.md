# 锚点与 frontmatter 约定

本文件是统一 skill `book2md1012` 与 Obsidian 插件 `aihistory-pdf-sync` 之间唯一的接口。两边任何一边要改这里的格式，先改本文件，再改代码。

「写的一方」指导入、补锚点、修订的脚本；「读的一方」指插件、verify、audit。写的一方照规则写；读的一方对旧数据、外来笔记从宽。

## 一、frontmatter：`pdf`

拆出的每个 Markdown 文件（卷首、正文、书末、索引都算）frontmatter 都有：

```yaml
pdf: "[[<原件或文字层副本>.pdf]]"
```

- 值是 Obsidian 内链，必须加引号（YAML 里 `[[` 开头不加引号会被读成嵌套列表）。
- 指向原件；原件是扫描件或文字层坏了、导入时另做了文字层副本的，指向副本 `<原件>.文字层.pdf`。原件始终保留、不改。
- 只写文件名，不写路径：PDF 与 Markdown 在同一个书文件夹里，Obsidian 按文件名解析内链。

**读的一方找 PDF 的顺序**：frontmatter `pdf` → `_数据/book.json` 的 `pdf` → 书文件夹（及上一级）里的 PDF：只有一个就用它；原件 `X.pdf` 与 `X.文字层.pdf` 都在时取文字层副本 → 与笔记同名的 PDF。

## 二、页码锚点

| 锚点 | 含义 |
|---|---|
| `<!--pdf-page.N-->` | PDF 第 N 页（物理页，从 1 起）内容的起点 |
| `<!--p.M-->` | 印刷页 M |

插件解析用的正则（两种都要认）：

```
<!--pdf-page\.(\d+)-->
<!--p\.([^>]+?)-->
```

### 写的规则

1. **每个物理页一个** `<!--pdf-page.N-->`，正文里按原 PDF 的页序排；新导入的书全书覆盖第 1 页到最后一页，空白页、插图页、版权页也写，锚点独占一段。
2. 段落跨页时，下一页的锚点插在**接缝处**（段中），即 MinerU 把两页拼成一段的位置（3.x 结构里 span 的 `cross_page: true`；4.0 结构里的 `continues_prev`）：

   ```
   ……坚持通过强化中央集权、官僚<!--pdf-page.2--><!--p.108-->军国主义，更大规模地……
   ```

3. 不跨页时，锚点在该页第一个块之前，独占一段。
4. `<!--p.M-->` 一般紧跟在同一页的物理页锚点之后、中间不留空格。没有可靠印刷页码的页（封面、扉页、插图页）不写 `<!--p.M-->`。印刷页按 MinerU 读到的页码推定（「印刷页 − 物理页」取众数补齐），推定的、跳号的页列进导入报告待核。罗马数字、汉字页码照录（`<!--p.iii-->`、`<!--p.三-->`）。
5. 锚点不进标题行。**页首就是章标题时**，物理页锚点独占一行、放在章标题之前；印刷页锚点可以留在原处（如标题之后），两者分开写。每个物理页最多一个 `<!--p.M-->`，它属于在它之前最近的那个物理页锚点。
6. 多文件的书：章首页的锚点独占一段、紧挨在章标题前时，跟着章标题进新文件（新文件以锚点开头）。**一页跨两个文件时**（页的前半属上一章），锚点写在前一个文件里；后一个文件开头再写一次这一页的锚点，叫「续页锚点」，形式与原锚点相同、独占一段，是文件里的第一段正文。续页锚点是全书唯一允许的重复，只能在文件开头。
7. 扫描件本身页序乱（装订错、扫描漏页后补扫）时照实写原 PDF 的页号，允许局部倒序；不为凑单调而改页号。

### 读的规则

- 两个锚点之间的内容算前一个锚点的页；文件开头、第一个锚点之前的内容，有续页锚点就按它，没有就按上一个文件最后一个锚点的页（「按下一个锚点的前一页推算」作兜底）。
- 旧数据和外来笔记可以缺页：缺的页按「两个锚点之间算前一页」容忍，不报错。
- 遇到倒序、页序乱：只提示，不报错。
- 同一物理页在一个文件里出现两次（续页锚点除外）：提示，取第一次。

### 旧格式兼容

md1012 时期的成品只有 `<!--p.M-->`（印刷页），没有物理页锚点。读的一方遇到只有 `<!--p.M-->` 的文件，按 `_数据/book.json` 的 `printedPageOffset` 换算物理页；写的一方（导入、补锚点）只写新格式。

## 三、脚注定义

```
[^n]: <!--pdf-page.N--><!--p.M--> 注文
```

- N 是注文开头所在的物理页，M 是该页印刷页（没有就省掉）。
- **脚注跨页**：允许在注文中间的接缝处再插一个物理页锚点：`[^n]: <!--pdf-page.N--><!--p.M--> 前半……<!--pdf-page.N+1--><!--p.M+1-->后半`。导入时不强求；audit 或 fix 发现后，征得用户同意再补。
- 脚注定义里的锚点不算正文锚点：「每页一个、覆盖全书」只查正文区；注释区的锚点只要求页号在全书范围内。
- 脚注号全书（或全文件）连续，`[^1]` 起；注释区写在章末或文末 `---` + `## 注释` 之后。
- 注释区从 `## 注释` 起，到下一个标题行**或下一个独占一行的物理页锚点**为止（下一章首页的锚点紧挨在章标题前，正落在上一章注释区之后，它属于正文）。

## 四、书文件夹

```
<书>/
├─ <原件>.pdf                  原件，只读
├─ <原件>.文字层.pdf           需要时（扫描件、文字层坏的 PDF）
├─ 00-可跳转目录.md            可跳转目录（索引笔记）：各篇链接与页码，排在最前
├─ 01-原书目录.md、02-前言.md、03-正文.md …   成品（原书自己的目录篇一律叫「原书目录」）
├─ <书名>.AI校注.md            校注，与正文分开
├─ <书名>.疑字清单.md          有未决疑字时
└─ _数据/
   ├─ book.json               书的配对信息（下节）
   ├─ MinerU/                 MinerU 原始结果，只读
   ├─ PaddleOCR/              PaddleOCR 逐页原始结果，只读
   ├─ 冲突清单/               两家识别对齐后的冲突清单
   └─ 过程报告/               脚本报告、骨架、整理前快照
```

## 五、`_数据/book.json`

第 2 版**只加字段、不删旧字段**：旧教材的第 1 版照样能读，note1012 旧的读法（`id`、`title`、`pdf`、`index`、`printedPageOffset`、`ocrBackend`、`writingMode`、`rebuild`）对第 2 版也照样能用。导入时写：

```json
{
  "version": 2,
  "id": "lunzhu2md-6491a14ba5",
  "title": "新史學",
  "pdf": "新史學.文字层.pdf",
  "originalPdf": "新史學.pdf",
  "pageCount": 23,
  "printedPageOffset": 4,
  "writingMode": "horizontal-tb",
  "indexNote": "00-可跳转目录.md",
  "files": [
    {"path": "01-中國之舊史.md", "pdfPages": [1, 11], "printedPages": "1-7"},
    {"path": "02-史學之界說.md", "pdfPages": [12, 16], "printedPages": "8-12"},
    {"path": "03-論正統.md", "pdfPages": [17, 23], "printedPages": "13-19"}
  ],
  "generator": "lunzhu2md 0.1.0"
}
```

| 字段 | 中文名 | 版本 | 说明 |
|---|---|---|---|
| `version` | 版本 | 1、2 | 本约定为 2 |
| `id` | 书的编号 | 1、2 | 库内唯一。第 2 版由 `lunzhu2md-` 加书名哈希前 10 位生成；旧书沿用原编号 |
| `title` | 书名 | 1、2 | |
| `pdf` | 配对 PDF | 1、2 | 相对书文件夹的路径；与 frontmatter `pdf` 指向同一个文件（有文字层副本时是副本） |
| `printedPageOffset` | 页码偏移 | 1、2 | **物理页 = 印刷页 + 偏移**。例：偏移 8，印刷页 p.1 在 PDF 第 9 页；论文从 p.107 印起、PDF 第 1 页就是 p.107，偏移为 −106。取全书「物理页 − 印刷页」的众数；前后页码体系不同时以正文为准 |
| `writingMode` | 书写方向 | 1、2 | `horizontal-tb` 表示整理后的 Markdown 阅读方向；原 PDF 可为竖排，不能据此字段拒收竖排材料。本次不改变字段取值或插件排版行为 |
| `index` | 逐字映射索引 | 1 | 旧书的 `_数据/映射/index.json`。第 2 版不写（没有逐字映射）；读的一方没有它就不用映射 |
| `ocrBackend` | 旧识别后端 | 1 | 旧书的 `onnx` 等。第 2 版不写 |
| `rebuild` | 旧重建配置 | 1 | 旧书的 `{"config": "_数据/config.json"}`。第 2 版不写 |
| `originalPdf` | 原件 | 2 | 有文字层副本时记原件；没有就与 `pdf` 相同 |
| `pageCount` | 物理页数 | 2 | 原 PDF 的总页数 |
| `indexNote` | 索引笔记 | 2 | 书的可跳转目录 Markdown，新导入的书固定为 `00-可跳转目录.md`（旧书可能是 `<书名>.md`，读的一方按这里写的名字找），可省 |
| `files` | 文件列表 | 2 | 按原书顺序，只列有锚点的成品文件（索引不列）。每项 `path` 相对书文件夹；`pdfPages` 是这个文件管的物理页范围 `[首, 末]`（含续页锚点那一页；文件里没有锚点时按上一文件的末页）；`printedPages` 是印刷页范围，可无 |
| `generator` | 生成工具 | 2 | 如 `lunzhu2md 0.1.0` |
| `conventions` | 凡例 | 2（可选） | 本书编辑体例，默认保真由 AI 记录；用户要求改变体例时记录其决定，见下节 |

### 凡例 `conventions`

凡例是「一本书的编辑体例」：AI 据原页记录，默认保留字形和标点、据目录与正文恢复标题，不要求用户确认技术映射。用户明确要求统一字形或标点时记录其决定。`confirmed` 仍只表示用户实际确认的日期；AI 自行记录默认体例时省略该字段，不能伪造用户确认。只记这一本书，下一本重新核原页。见 [division-of-labor.md](division-of-labor.md)。

```json
"conventions": {
  "confirmed": "2026-10-21",
  "punctWidth": "fullwidth",
  "headingLevels": [
    {"form": "第X章", "level": 1},
    {"form": "第X節", "level": 2},
    {"form": "一、", "level": 3}
  ],
  "glyphs": "keep",
  "notes": "引文里的半角标点照原书；表格不动。"
}
```

| 字段 | 中文名 | 说明 |
|---|---|---|
| `confirmed` | 确认日期 | 用户确认这套凡例的日期 |
| `punctWidth` | 标点宽度 | `fullwidth` 整本中文语境统一全角（据此跑 `punct_width.py`）；`keep` 保留原样。没有这一项 = 没定，不跑 |
| `headingLevels` | 标题级映射 | 编号形态 → 标题级（`level` 为 Markdown 的 `#` 个数）。依据是目录原页的缩进与正文；**目前没有脚本读它**，由 AI 按映射手工改标题级并整批报告 |
| `glyphs` | 字形 | `keep` 保留原书字形；`normalize` 统一成规范字形（只在有原图依据时替换） |
| `notes` | 其他说明 | 自由文字：哪些语境（西文、数字、引文、表格）例外 |

兼容：`conventions` 整个可省，各子项也都可省；读的一方（插件、脚本）不认识的字段一律忽略。`split_book.py` 重写 `book.json` 时保留已有的、它自己不写的字段，所以先记的凡例不会被冲掉。

## 六、疑字清单条目的链接

```
obsidian://aihistory-pdf-sync?vault=<库名>&file=<库内相对路径>&page=<N>&text=<现字>&ctx=<上下文>
obsidian://aihistory-pdf-sync?file=<书文件夹名>/<文件名>&page=<N>&text=<现字>&ctx=<上下文>      （书不在库里时）
```

- **链接一律写**。参数都做 URL 编码（UTF-8 百分号编码，`file` 里的 `/` 也编码）；`file` 不带开头的 `/`。
- 书在 Obsidian 库里：从书文件夹往上找含 `.obsidian` 的目录，且它必须登记在 Obsidian 的库清单（`obsidian.json`）里；`vault` 取该目录名，`file` 是库内相对路径。
- 书不在登记过的库里：省掉 `vault`，`file` 写「书文件夹名/文件名」。读的一方在当前库里找路径以它结尾的文件（书放进库里之后照样能跳）。
- `page` 是物理页 N。`text` 是正文里现在的字（一般 1–4 字；一家漏读时可以为空）。
- `ctx` 是含现字的上下文：**前约 6 字 + 现字 + 后约 6 字**，取正文原样（含标点与 Markdown 记号），不跨页码锚点、不跨段落。
- 插件在第 N 页的锚点段内找 `text`，多处命中时用 `ctx` 消歧，选中并带动 PDF 翻到该页。

skill 改名为 Book2MD1012 后，已有书的 `lunzhu2md-` 编号、`_lunzhu2md_source.json` 来源文件及锚点格式继续沿用，不批量改写。

## 修订请求格式（插件 → book2md1012）

插件「复制本页修订请求」生成的文字，以插件仓库的 `obsidian/src/core/revision.ts` 为准，`book2md1012` 的修订流程照此解析（兼容旧版请求中的 `lunzhu2md-fix`）。

```
请用 book2md1012 按原页修订：PDF 第 N 页（印刷页 p.M）。
- 笔记：<笔记绝对路径；拿不到时给库内路径>
- PDF：<PDF 绝对路径>
- 锚点：<!--pdf-page.N-->
- 本页开头：<本页正文去掉锚点后的前约 30 字>
- 本页结尾：<后约 30 字；本页不足 60 字时省去此行>
- 选中的文字：<用户选中的文字；没选时省去此行>
- 问题：（在这里写哪里丢了、错了；没写就请对照原页通查本页）
```

- 印刷页未知时，首行省去「（印刷页 p.M）」。
- 字段名（笔记、PDF、锚点、本页开头、本页结尾、选中的文字、问题）是接口，改动须两边同改。
