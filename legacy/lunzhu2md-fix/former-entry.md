# lunzhu2md-fix：按页修订

导入后的正文只改 Markdown。本 skill 一次只修一页：以 PDF 原页为准，把这页的正文与脚注改对，别的页一个字不碰。

工具脚本：`python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/page_tool.py <子命令> …`（下文简写 `page_tool`）。`${CLAUDE_SKILL_DIR}` 指本 SKILL.md 所在的目录：Claude Code 会自动替换；在 Codex 等别的平台上没被替换时，自己代入本文件所在目录的绝对路径。
锚点约定见 `../lunzhu2md/references/anchors.md`，要点：

- `<!--pdf-page.N-->`：PDF 第 N 页（从 1 起）内容的起点，段落跨页时插在段中接缝处；
- `<!--p.M-->`：原书印刷页，紧跟物理页锚点；
- 脚注定义 `[^n]: <!--pdf-page.N--><!--p.M--> 注文`，自带它所在的页；
- frontmatter `pdf: "[[原件.pdf]]"` 指明配对的 PDF。

## 分工：脚本做机械活，判断归你

- 脚本（`page_tool.py`）只做确定的机械活：找 PDF、取本页锚点段与脚注、渲染页图、读文字层、按一句话查页、备份、核对改动范围（`guard`）。遇到异常只报告，从不改正文。
- 内容上的判断由你（对话里的 AI）做：脚本的输出是证据，不是结论。每一处要不要改、改成什么，都对照原页图决定，并向用户说明理由；拿不准就问用户。
- 不为少见情况去改脚本、加自动修补规则；遇到脚本没覆盖的情况，人工处理并在报告里写明。
- **用户不在场或说“按推荐先做”**：只修点名那一页、那一个问题；同页别的错、标题层级、锚点、别页问题都算另一件事，只列不改。推荐不是授权；做不到就停下列清单，不猜。
- **证据**：每条内容改动都要能指出页码锚点和原图上的细节（字形、表格线、版式）；指不出就是没看原页。

## 一、先弄清「哪个文件、哪一页」

| 用户给的 | 怎么定位 |
|---|---|
| 「PDF 第 N 页」、`obsidian://…&page=N` | 物理页 N，直接用 |
| 插件请求 | 首行形如「请用 lunzhu2md-fix 按原页修订：PDF 第 N 页（印刷页 p.M）。」，其后有「笔记：<绝对路径>」「PDF：<绝对路径>」「锚点」「本页开头」「本页结尾」「选中的文字」「问题：」。按「笔记」和「PDF 第 N 页」定位；「问题」是用户要修的事，「选中的文字」是用户在正文里选的位置。粘来的正文片段只作参考，一律以磁盘上的文件为准 |
| 「原书第 M 页」「p.M」 | `page_tool extract <书> --printed M`，脚本换算成物理页 |
| 只说「第 N 页」 | **默认按原书页码**：`--printed N`。动手前用一句话告诉用户「按原书第 N 页（PDF 第 K 页）处理，若指 PDF 第 N 页请说」。正文里没有 `<!--p.N-->`（如无页码的卷首、插图页）时才按 PDF 第 N 页，同样告诉用户 |
| 一张截图 | 图上印的页码是原书页码，用 `--printed`；看不到页码就从图里抄一句不短于 8 字的原文，`page_tool search <书> "那句话"`，看它在 PDF 哪页、正文哪页 |
| 「某句话不见了」 | 同上，用 `search`；`pdf_pages` 有、`md` 为空，就是正文丢了 |

`--printed M` 若报「对应多个物理页」（例如卷首罗马页码与正文页码重号），把候选页开头各一句给用户看，问清后改用 `--page`。

`<书>` 可以是某个 `.md`，也可以是书文件夹（多文件的书会自动找到含这一页的文件）。用户在 Obsidian 库里说的路径，按库根拼成绝对路径。

旧成品只有 `<!--p.M-->`、没有物理页锚点时：书文件夹的 `_数据/book.json` 有 `printedPageOffset`（页码偏移）就能照常用，脚本按「物理页 = 印刷页 + 偏移」换算，`extract` 会注明「旧格式」；没有就告诉用户这份需要先补物理页锚点（插件的「补页码锚点」），本 skill 不补。

## 二、看原页、取本页正文

```bash
python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/page_tool.py locate  "<书>"                 # 找到的 PDF、怎么找到的、共几页
python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/page_tool.py extract "<书>" --page N --numbered   # 本页锚点段 + 挂在本页的脚注（带行号）
python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/page_tool.py render  "<书>" --page N --dpi 150 --out "<草稿目录>/pN.png"
python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/page_tool.py pdftext "<书>" --page N             # 文字层，辅助比对
```

- 用 Read 工具看 PNG。小字、表格、注码看不清就再出 200 dpi，或用 Read 直接按页读 PDF（`pages: "N"`）。
- PNG 放会话的草稿目录（scratchpad）；不给 `--out` 时放系统临时目录。不要放进书文件夹或库里。
- `extract` 会列出：本页正文（从本页锚点到下一页锚点）、挂在本页的脚注定义、本页注码但定义不在本页的、本页定义但找不到注码的；一页拆在两个文件时，还列出下一个文件锚点之前属于本页的部分。脚注定义一般集中在文件末尾「注释」下，行号以输出为准。
- 文字层可能本身有错，也可能就是 MinerU 写进去的；**只有页图是依据**。
- 找不到 PDF 时，`locate` 会说明按什么次序找过（frontmatter `pdf` → `_数据/book.json` → 同文件夹唯一 PDF），把它告诉用户，请用户指出 PDF，不要随便配一个。

## 三、对照原页逐项核

按页图从上到下，对正文和脚注逐项核：

1. **段落**：有没有整段、半段漏掉；有没有两段并成一段、一段拆成两段（串段）；跨页的段落在接缝处是否接得上。
2. **脚注**：页脚每一条注是否都在；注码 `[^n]` 是否在正文对应位置；注文有没有串进正文、正文有没有串进注文。
3. **标题**：有没有漏标题；标题层级（`#` 个数）是否与全书同级标题一致；编号是否连贯。
4. **表格、图、引文块**：表格行列、表题、表注；图题；独立引文段（如律令条文）。
5. **页眉、页脚、页码、水印**：混进正文的要删。
6. **错字**：只改 OCR 误识，见下面保真规则。

先把发现的问题列成清单（第几段、原页作什么、正文作什么、打算怎么改）。

- 用户点名要修的问题，直接改。
- 核对中顺带发现的本页其他问题，先列给用户，问要不要一并改，不要自行扩大范围。
- 拿不准的（字迹不清、疑似原书误印、两种读法都通、要动别的页或锚点），列给用户，等用户定。

## 四、保真规则

- **以原件为准**：唯一依据是 PDF 页图。MinerU、PaddleOCR、文字层、AI 的「常识」都只是参考。
- **原书误印照录**：原书本身印错的字、错的引文、错的编号，不改；在校注「存疑未改」一节记一句。
- **只改识别错误**：不润色、不改写、不统一用字、不把异体字改成正字、不改原书标点体例；全角半角跟本文件其余部分一致。
- **改字记校注**：每改一处字词（含补字、删字），在 `<书名>.AI校注.md` 的表里记一行（见第六节）。补回整段、整注、表格、标题这类结构性修复，也记一行，「底稿」栏写「（缺）」。
- **只动本页**：只改第 N 页锚点段和挂在第 N 页的脚注定义。发现别页也有问题，记下来告诉用户，另起一次修。
- **锚点不动**：`<!--pdf-page.N-->`、`<!--p.M-->` 一个都不增、不删、不挪，也不改脚注定义里的锚点。锚点本身放错了，按下面「锚点放错」一步处理，不在修页时顺手改。

## 四之二、锚点放错：停下、给建议、用户同意才改

三种情况：

- **正文锚点不在接缝处**：锚点后的头几个字在原图上属于上一页（放早了），或锚点前的末几个字属于下一页（放晚了）。`extract` 前后两页对照原图即可看出；lunzhu2md-audit 的「锚点错位」也会报。
- **注文挂错页**：脚注定义里的 `<!--pdf-page.N-->` 与原图上这条注所在的页不符。
- **注文跨页而没标续页锚点**：原图上一条注从第 N 页页脚续到第 N+1 页页脚。约定允许（可选）在注文的接缝处再插一个锚点，写成 `[^n]: <!--pdf-page.N--><!--p.M--> 前半……<!--pdf-page.N+1--><!--p.M+1-->后半……`，插件和脚本据此把后半算到第 N+1 页。导入时不强求，是否补由用户定。

处理：

1. 停下，不改。用不懂技术的人能看懂的话告诉用户：锚点是正文里看不见的页码标记（`<!--pdf-page.N-->`），标出 PDF 第 N 页从哪个字开始；Obsidian 插件靠它让左边的 PDF 跟着翻页，放错了，翻到这里时 PDF 会对不上页。
2. 给建议：现在在哪（引锚点前后各十来个字）、原图上第 N 页实际从哪句开始、建议挪到哪、会牵动哪两页（第 N−1 页与第 N 页），附原图证据（哪一页的第几行）。
3. 等用户同意。用户不同意或没回话，就不改。
4. 同意后：`snapshot` → 用 Edit 挪动这一个锚点（物理页锚点连同紧跟的 `<!--p.M-->` 一起挪）→ 守卫放行两侧两页并声明挪锚点：

   ```bash
   python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/page_tool.py guard "<备份.md>" "<文件.md>" --page <N−1> --page <N> --anchor-move
   ```

   注文挂错页时，改的是那条脚注定义里的锚点，`--page` 给改前、改后两个页号。补注文续页锚点时，`--page` 给 N 与 N+1 两页。
5. 在校注记一行：「位置」写两页，「底稿」写原锚点位置，「改作」写新位置，「依据」写「据原图，第 N 页始于『……』」。

## 五、改的写法

1. 改之前先备份：

   ```bash
   python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/page_tool.py snapshot "<文件.md>"
   ```

   打印出备份路径（`<书>/_数据/过程报告/fix-备份/<文件名>.<时间>.md`），记住它。

2. 用 Edit 工具改，`old_string` 取本页里能唯一定位的一段原文。不要整页重写。
3. 各类修法：
   - **补段**：插在原页对应位置，前后各空一行。本页的内容一律放在本页锚点之后、下一页锚点之前；漏的若是跨页段落在**上一页**的那半段，它属于上一页，另修上一页，不要放到本页锚点之前。
   - **补注**：正文按原位置加注码，注文加在文件的脚注区，写成 `[^标签]: <!--pdf-page.N--><!--p.M--> 注文`（`p.M` 照本页锚点），放在本页其他注的定义旁边。标签：
     - 该号空着（注号跳号，比如有 [^29]、[^31] 没有 [^30]）：直接用那个号，不必问。
     - 号已被占（导入时整条注连注码一起漏掉，后面的注已经顺着编下去了）：**先问用户**，两种办法二选一，说明原因：
       ① 用 `[^pN-1]`、`[^pN-2]`……（N 为物理页）这类标签（推荐）。只动本页；Obsidian 显示脚注时按出现次序自动编号，读者看到的序号照样连续，标签名只是内部记号。缺点：标签和别的注不同形，一眼能看出是后补的（这也正好留了痕迹）。
       ② 按原书注号：本条用原书的号，其后全文件的注号依次顺延。读起来最整齐，但要改全文件后面每一条注的注码和定义，牵动很多页，只能整文件做一次，改前备份、改后逐条核对。
     用户选了哪种，在校注里记一笔。
   - **标题**：层级照全书同级标题；编号照原书。
   - **表格**：跟本文件已有表格的写法一致（HTML 表格就用 HTML，Markdown 表格就用 Markdown）。
   - **串段**：按原书断段；正文里混进的注文移回脚注区（锚点照原样带上），注文里混进的正文移回正文。
   - **页眉页脚、水印**：整行删除。
4. 改完跑守卫：

   ```bash
   python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/page_tool.py guard "<备份.md>" "<文件.md>" --page N
   ```

   它核对：锚点序列一个不差、frontmatter 未变、除第 N 页正文和挂在第 N 页的脚注（含新补的注）外，其余一律未变。不通过就照提示改回，直到通过。（挪锚点见第四之二节；按原书注号整文件改号时守卫必然不通过，改为逐条核对注码与定义一一对应，再跑 `pages` 看脚注数。）
5. 再跑一次 `extract … --page N`，确认「找不到定义」「找不到注码」两类不再有本次该修好的项。「定义挂在别的页」若是注文锚点错了，按第四节的锚点例外处理，不在这里改。

## 六、校注

校注文件是书文件夹里的 `<书名>.AI校注.md`：先找书文件夹里已有的 `*.AI校注.md`，有就用它；没有时，`<书名>` 取 `_数据/book.json` 的 `title`，再没有就取书文件夹名。已有就在表末续一行，**沿用文件里已有的表头**；没有就新建：

```markdown
---
title: <书名> 校注
---

# 校注

| # | 位置 | 底稿 | 改作 | 依据 |
|---|---|---|---|---|
| 1 | PDF 第 7 页（p.113），第 2 段 | 捕诫告者 | 捕诇告者 | 原图作「诇」 |

## 存疑未改（原刊如此）

- PDF 第 4 页（p.110）「秦令（11）」：所述实为秦令（10），疑原刊误印，照录。
```

- 「位置」写物理页（印刷页），再写第几段、注几；「依据」写原图所见，或「据原图补回整段」。
- 若改动解决了 `<书名>.疑字清单.md` 里本页的某条，在那条末尾加「（已据原图改为 X，YYYY-MM-DD）」，不要删条目。

## 七、整页坏到没法修

整页大面积乱码、版面全错、表格完全散了，手改成本远高于重跑时，可以用 MinerU 新接口（V1 的 `page_range`）只重跑这一页再合并。**这会调用外部接口、消耗额度，必须先问用户**，说明要重跑哪一页、为什么。

用户同意后，用导入 skill 的 MinerU 客户端只交这一页（交**原件**，不是 `.文字层.pdf` 副本；原件名见 `_数据/book.json` 的 `originalPdf`）：

```bash
python -X utf8 ${CLAUDE_SKILL_DIR}/../lunzhu2md/scripts/mineru_v1.py submit "<书>/<原件>.pdf" -o "<书>/_数据/MinerU" --ocr-mode ocr --page-range N
```

- 结果落在 `<书>/_数据/MinerU/<原件>.pages-000N-000N.mineru/`，不覆盖导入时的原始结果。令牌由客户端自己读，不要打印、不要自己拼请求。
- 同一文件再次提交时 V1 可能不理 `ocr_mode`、返回缓存结果，客户端会自动退回 v4 接口，属正常。
- 从结果里取本页正文：读该目录下的 `*_content_list.json`（或 `full.md`），只要这一页的块；页眉、页脚、页码块丢掉。

合并做法：只取重跑结果里这一页的正文与脚注，替换本页锚点段（锚点照原样保留在原位置，跨页接缝处的半段照第三节核对），脚注按第五节的写法加锚点；重跑结果同样要对着原图核，不能直接当准；再跑守卫，并在校注记一行「PDF 第 N 页：据 MinerU 单页重跑结果重排」。

## 八、收尾报告

告诉用户：改了哪个文件、第几页；逐条列出改动（补了什么、删了什么、改了哪几个字）；校注记了几行；守卫是否通过；顺带发现、没有动的别页问题；需要用户定的事。
