# PaddleOCR：默认交叉核对的第二家云端服务

## 它是什么、为什么要

`paddle_api.py` 把 PDF 交给百度飞桨星河社区的 **PaddleOCR-VL** 云端接口，逐页返回版面与文字，
下游 `crosscheck.py` 拿它跟 MinerU 的结果按物理页对齐，出冲突清单。

作用是**第二读者**：两个模型读同一页，读得不一样的地方才值得看。只有一家时，报告必须写「无第二读者覆盖」——
这不是形式要求，是让读报告的人知道哪一部分没有交叉验证过。

## 令牌从哪来

首次引导优先由 AI 打开 `configure_tokens.py`，在同一个本机窗口配置两家，保存与验证分别显示。无图形会话时才给终端隐藏输入命令，详见 [get-token.md](get-token.md)。

服务是 `https://paddleocr.aistudio-app.com/api/v2/ocr`（写在 `paddle_api.py` 的 `API_BASE` 里）。
去这个服务的控制台用百度账号开通、创建访问令牌；**具体入口页以控制台为准**，不要在文档里写死可能变动的路径。

拿到令牌后有三个放法，按优先级：

| 方式 | 怎么做 | 适合 |
|---|---|---|
| 本机存一次（推荐） | `python paddle_api.py configure`，隐藏输入 | 个人常用 |
| 环境变量 | `PADDLEOCR_ACCESS_TOKEN` | CI、临时机器 |
| 令牌文件 | `--token-file <路径>` | 多账号切换 |

Windows 上本机存盘走 DPAPI 加密，与 MinerU 令牌同一个配置目录（`%APPDATA%\mineru-skill\`）。

**绝不**把令牌贴进聊天、写进仓库、放在命令行参数里（会进 shell 历史）。

## 开工先查，别等到交第二家才发现

```bash
python paddle_api.py status
```

- 退出码 `0`：`CONFIGURED source=local-config|env|token-file model=…`
- 退出码 `3`：`NOT_CONFIGURED hint=...`——按 get-token.md 帮用户补配；不能自行降为单家。

不联网，不读令牌内容，只报「有没有、从哪来」。

## 模型

默认 `PaddleOCR-VL-1.6`。`check-models` 会探测有没有更新的模型（最多每 30 天一次），
`use-model <名>` 切换默认值。不要为了追新模型重跑整本书——重跑只补未解析的页。

## 配额、隐私与代价

- 每日有页数上限（按账号）；单文件上传上限约 50 MB，脚本按 45 MB 分卷。
- PDF **会上传到百度**。未刊稿、有保密顾虑的材料，上传前先问用户。
- 双家识别的 API 开销与 AI 看图核对分开记录：仅核冲突只读不同字及必要上下文、结构分歧区域；全书模式另逐页逐字核图。处理前按 verification-modes.md 取得用户选择。

## 出错怎么办

| 现象 | 处理 |
|---|---|
| `NOT_CONFIGURED` | 引导本机 `configure`；未配置则该步骤待完成，只有用户明确选择单家才按单家交付 |
| 401 / 403 | 令牌错或过期，重新 `configure` |
| 413 或上传失败 | 用 `--pages` 分段（脚本已按 45 MB 分卷，仍失败就手动切） |
| 超时 / 中断 | 直接重跑：已解析的页会跳过，只补缺的 |
| 部分页失败 | 脚本会打 `PARTIAL … failed_pages=…`，重跑补；补不上就在交付报告里记哪几页没有第二读者 |

## 没有令牌时怎么写报告

不要含糊。写清楚三件事：用户选的是哪一档、第二家为什么没跑、用什么替代核验了（例如原件自带文字层）、
以及哪一部分因此没有交叉验证。默认双家任务缺第二份结果时，交叉核对仍未完成；不能把替代核验写成两家均已覆盖。
