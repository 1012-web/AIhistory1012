# 交付：写给拿到书的人

交付有两份，别混。

- `_数据/过程报告/_交付报告.md`：给复核者看的，指标写全（页覆盖、接口、`ocr_mode`、冲突条数、未决项）。
- 对话里的交付：给拿到书的人看的。他要的不是「验证通过」，是「我手上这本能不能用、哪里要留神」。

交付写明用户所选的“仅核双家冲突”或“全书逐页逐字核对”，以及实际核过的冲突区域或逐字页数；不能用“逐页查看”代替覆盖记录。仅核冲突时说明两家共同错误可能保留。

交付说明不能替代事前许可。若原计划使用双家结果完成整理，却拟改用旧文字层、少用一家或省略整理核对，先按 [division-of-labor.md](division-of-labor.md) 交互说明原因、范围与影响，取得明确许可再做。未获许可时只能报告待完成部分，不能把未经核对的文字层导出称为“整理完成”。

## 一、三步，顺序不能换

### 1. 拿到什么

先说成品本身：几页、哪些篇、注在不在、图和表在不在、和原件对不对得上。

> 书导入好了，在 `新史學/`。梁启超《新史學》三节，23 页，11 条页下注，一张校订说明表，页序照原书。

反例（这是在报账，不是交书）：

> 处理的页：PDF 第 1—23 页；锚点 23/23；`verify.py --book` 全过；成品 `01-正文.md`。

### 2. 能不能信

改了几处、依据是什么；举两三个最能说明问题的例子（读者一看就知道你为什么改）；再说拿不准的有几处、他可以怎么核。

> 我改了 18 个字，都是识别读错、原书是对的——比如「效顰」「夾漈」「齗齗」「蕭巋」。还有 3 处拿不准（异体字形、目录点线），没敢动，记在 `新史學.AI校注.md` 里，你看一眼就能定。

### 3. 哪里要自己核

没做到的明说，不藏：没看页图、没有第二读者、哪些页只是抽样、哪些页文字层是坏的。

> 经你选择，本次只交原 PDF 文字层的临时导出稿，不含双家交叉核对及脚注重建。它不是约定的整理成品；待恢复识别结果后再继续原流程。

## 二、术语换成人话

只在需要用户判断的地方出现，出现就当场解释：

| 内部说法 | 对人怎么说 |
|---|---|
| `<!--pdf-page.N-->` 锚点 | 每页的隐形书签，插件靠它把 PDF 和正文对齐 |
| `ocr_mode`、退回 v4 | 用哪条路识别的（用户只需要知道「这条路会不会吞标点」） |
| 冲突清单 | 两家识别读得不一样的地方 |
| `verify.py` 通过 | 页码对得上、脚注没有孤立引用 |
| 核对方式 | 实际用了哪些识别服务、哪些地方核了原页 |

## 三、成品说明（随书给，可选）

分发或入库时，另写一份给读者看的短说明，避免他打开一堆文件发懵：

```markdown
# <书名> · 怎么用

本文件夹是从 `<原件>.pdf` 导入的 Markdown，页序与原件一致，每页文内有一个隐形书签。
在 Obsidian 里同时打开 `01-正文.md` 和原 PDF，右边会跟着左边翻页。

- `<书名>.md`  目录页
- `01-正文.md` 正文（卷首 + 各章）
- `<书名>.AI校注.md`  我改过的字、没定的疑问
- `_数据/`  识别原稿与逐页比对报告，平时不用打开

没做到的：<没看页图 / 无第二读者 / 抽样范围>。
```

## 四、交货前自查

1. 打开 Markdown 成品检查实际文字、标题和脚注呈现，不只读报告。仅核冲突模式不能借此查看无冲突原页；全书模式另核逐页逐字覆盖。
2. 段落有没有被并、标题有没有归错、表格有没有串行、页眉有没有混进正文。
3. 交付里有没有一处术语没解释。
4. 没做到的事有没有写进「哪里要自己核」。
