# 文字层副本：找行、对字、交 AI 定的几类、写入

导入流程第 5 步。扫描件（或文字层坏的 PDF）另存一份 `<原件>.文字层.pdf`：页面图像不变，盖一层看不见的字，PDF 里就能搜索、复制，插件的逐字高亮、补页码锚点也能用。原件不动。

**字用 MinerU 的**（与 Markdown 正文同一份），**位置用找行的行框**。MinerU 走 OCR 时一块只给一个整段的框，不知道每行在哪，所以行框另向 PaddleOCR 云端要。

## 1. 找行：`paddle_lines.py`

```powershell
python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/paddle_lines.py submit <书>/<原件>.pdf -o <书>/_数据/PaddleOCR行框 [--pages 1-339]
```

- 用 PaddleOCR 云端的普通识别（PP-OCRv6），只取行框；它认的字附在行框文件里，只作参考。令牌与 `paddle_api.py` 共用（`configure` 存的那份，或 `--token-file`）。
- 页面上传到百度飞桨服务器。扫描件在双家流程里本来就交过 PaddleOCR-VL，不新增暴露面；未刊稿、用户不愿上传的先问。
- 实测（2026-10-20，专著 10 页）：378 行一行没漏，MinerU 的字 99.95% 能对上某一行；10 页整批 9 秒。免费额度每天 2 万页。
- 已有原始结果时：`paddle_lines.py convert <原始.jsonl> --pages 4,7,11 -o <行框.json>`。

### 行框文件格式

换别家找行时，照这个格式写一份交给 `assign` 就行，不用改代码：

```json
{"version": 1, "source": "PaddleOCR PP-OCRv6", "units": "fraction",
 "pages": {"11": {"lines": [{"box": [0.11, 0.06, 0.89, 0.08], "text": "该行 OCR 认的字（可省）"}]}}}
```

- 页号是原 PDF 的物理页（1 起）；`box` 是 `[左, 上, 右, 下]`，相对页宽、页高的 0–1 比例，原点在左上。
- 行的顺序不要紧（对字时按位置排）；`text` 可省，省了就只能靠位置对字，准确度会降。

### 云端用不了时

令牌过期、服务出错，或用户不愿上传（如未刊稿）时，可以向用户提一句：「本机有 RapidOCR 可用：要另装约 255 MB 的独立环境，每页约 5 秒，偶尔漏行。」用户同意才装（独立 venv，`pip install rapidocr onnxruntime`；官方源慢时可换镜像），用它出行框，再照上面的格式写行框文件。不装就不做文字层，或先用 MinerU 自己的行框（下一节）。RapidOCR 不是自动后备，脚本里也没有它。

## 2. 对字：`pdf_textlayer.py assign`

```powershell
python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/pdf_textlayer.py assign --pdf <书>/<原件>.pdf --mineru <卷1>.mineru [--mineru <卷2>.mineru] --lines <书>/_数据/PaddleOCR行框/lines.json
```

机械的几步：

1. 按 MinerU 自己的跨页标记（`cross_page`，与 `build.py` 放物理页锚点用的是同一个）把跨页段落拆回各页：续行的字归下一页，放进那一页空出来的续段块的范围。
2. 每页把 MinerU 各块的字，与落在块框里的行按编辑距离对齐，字写到对上的那一行；夹在两个对上的字之间的，跟前一个字走。写进去的是 MinerU 的字，不是 OCR 的字。
3. 页码、页眉被 OCR 框进同一行的（「序论3」），并进那一行。
4. 写进每一行之前核一次：只比字母、数字、汉字，要写的字（8 个以上）里与这一行 OCR 认的字对得上的不到三成，或 OCR 一个字也没认出、要写的字又远超行框放得下的，就不写，列进报告「差得太远」一节。这一步专防识别模型在近乎空白的页上编出整段字（模型幻觉）：整块的字会全落到这页仅有的一行上，哪怕那一行只是一条横线。

产出 `_数据/文字层/assignment.json`（每页每行：框、要写的字、OCR 认的字、属于哪类区域）和 `文字层报告.md`。

不给 `--lines` 时退回 MinerU 自己的行框：文字层路线的 PDF 那是真的行；OCR 路线一块只有一个整段框，选字、高亮会落在整段上，报告会提醒。

## 3. 交 AI 定的几类

`文字层报告.md` 逐处列出，脚本都没有动：

| 类别 | 常见原因 | 怎么定 |
|---|---|---|
| 空着的行 | 表格（MinerU 表格的字顺序与行框对不上、或续表被并走了）；MinerU 漏读的行 | 看原页 |
| 放不进任何行的字 | 块首、块尾一长串字对不上本页任何一行，多半是别页的字（如续表）被并进了这一块 | 看原页，多半不用管 |
| 行框上 OCR 认的字与要写的字差得太远 | 空白页上模型编出的字（实例：一本专著第 46 页只有一条横线，MinerU 给了一整段英文推理文字）；也可能是行框找错了位置 | 看原页：页上没有就留空，并核正文里是否也混进了同一段；真有字才 `fill` |
| 疑似跨页表 | 这一页的表格块是空的，续表被并进了上一页的表；数据定不了哪几行属于这一页 | 看两页原图 |
| 有字但没有行框的页 | 行框文件没覆盖这些页 | 补找行，或不写这些页 |

**报告附的 OCR 字只作参考，不要直接拿来补。** 一本专著第 84–85 页的一张跨页表就是例子：

- MinerU 把两页的表合成一张放在第 84 页；第 85 页（续表）的表格区在文字层里全空，75 行；第 85 页的锚点落在整张表后面，读到续表时 PDF 停在第 84 页。
- 原书印的一个生僻字（两处），四家都认成形近的常用字。两家一致，冲突清单也抓不到；成品正文里也是错的。
- 云端 OCR 另把「痾」认成「病」、「金沴木」认成「金诊木」、空格里的「—」认成「一」。要是自动拿 OCR 的字补，这些错字会悄悄进文字层。

看原页后，每处三选一：

1. **正文本身错了**：先改 Markdown 正文（记校注、走 `diff_report.py`），再按改好的字写进那几行；
2. **正文没有这几行**（续表、漏读）：按原页核过的字写进去；
3. **留空**：拿不准、或不值得逐格核的（大表），留空并写进交付报告。

拿不准就问用户。写进某一行用 `fill`（行号就是报告里「第几行」）：

```powershell
python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/pdf_textlayer.py fill --assignment <书>/_数据/文字层/assignment.json --page 85 --line 3 --text "貌"
```

也可以直接改 `assignment.json` 里那一行的 `text`。跨页表的锚点要不要挪进表里续表开始处，在 Markdown 正文里改（见构建报告「疑似跨页表」）。

## 4. 写入：`pdf_textlayer.py write`

```powershell
python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/pdf_textlayer.py write --pdf <书>/<原件>.pdf --assignment <书>/_数据/文字层/assignment.json [--visible-text raster]
```

- 每行写成一条隐形文字：字号按行高，横向缩放到正好铺满行框（逐字分开写时阅读器抽出来一字一行，跨字搜不到）。
- 扫描页（删文字前后外观不变）删旧隐形层再写；字本来看得见的页默认原样保留；文字层坏了的用 `--visible-text raster` 把那页渲染成图（`--dpi`，默认 200）换进副本再写。
- 看 `_textlayer_report.json`：`pagesBelow99`（回读与要写的字对不上的页）、`fontMissing`（字体里没有的字）、`pendingInReport`（报告里还没处理的项数）。
- 报告里没有待定项时，可以用 `build` 一步做完 `assign` 加 `write`。
