# 官方版面能力与本 skill 的使用范围

代表页适用性验证先说明页范围与目的并取得用户许可；仅核双家冲突模式不因此授权通读全书。整理仍按 [verification-modes.md](verification-modes.md) 的范围，仅核冲突先比双家结果，只看分歧区域。

核对日期：2026-10-25。首次安装或用户要求引导时，用本页给出适用范围；正式处理时以调用接口的实际版本和代表页结果选择路线。官方声明、云端返回与本 skill 的恢复能力分别记录。

## 两家的官方说明

| 服务/组件 | 官方声明涉及的版面结构 | 对本流程的意义 |
|---|---|---|
| MinerU 精准解析云 API | 复杂及多栏布局，文本、表格、数学公式、图表和图片；提供结构化输出 | 适合论文、专著、教材等。脚注是否完整须检查原始版面数据，不能仅交付自动导出的 Markdown |
| MinerU 开源 3.0 pipeline 发布说明 | 增加竖排文本、表内图片/公式、印章文字及公式编号支持；后续发布增加截断段落与跨页表合并 | 不能再沿用「MinerU 不支持竖排」的旧断言；开源发布能力不能直接推定已部署在当前云 API |
| PaddleOCR-VL 系列 | 文本、表格、公式和图表；1.5 增加印章，1.6 宣称改善古籍和生僻字 | 本 skill 通过 PaddleOCR-VL 云端完整解析服务取得第二份结果，不是只请求一个裸 VLM |
| PaddleOCR 版面分析 PP-DocLayoutV2 | 文档/段落标题、正文、竖排文本、页码、摘要、目录、参考文献、脚注、图像脚注、页眉页脚及其图像、算法、行内/行间公式及编号、图片、表格、图表标题、印章、图表、侧栏等类别；训练场景含古籍和竖版文档 | 这是组件的检测与读序能力声明，不是保证当前云端端点对所有竖排夹注都能完整恢复 |

## 初次向用户怎么说

常规对象是论文、专著、教材以及现代排版古籍。MinerU 负责主体版面解析，PaddleOCR-VL 提供第二份识别，AI 整理标题、正文、脚注与逐页对应。两家官方均有复杂版面能力说明，PaddleOCR 的版面组件明确包含竖排类别；现代竖排点校本由 AI 先验证代表页的列序、标点和双行夹注，再选择可用路线。不能仅凭文献年代或「古籍」二字拒收，也不能把识别到文字等同于恢复好版面。

## 竖排路线如何决定

1. 抽取能代表本书的正文、注区/双行夹注、横竖混排页，以实际云端端点识别并对照原图。记录服务、请求模型、返回结构版本和缺漏；文字层解析不算已做 OCR。
2. 样页读序、正文与注区可用，才继续同一路线；局部缺漏由 AI 核图修复，不把结构检查交给用户。
3. 如果 MinerU 对这份材料仍有整栏漏读、读序或夹注结构不可用，接入看典古籍逐页图像识别作为竖排来源，与 PaddleOCR 交叉核对。向用户说明新增服务、上传范围和费用并取得相应授权；不擅自把原件上传第三家。
4. 保留原始结果及来源标签。看典只有正文/页眉页脚等较粗版面标签，不能伪装成 MinerU 脚注结构；AI 据原页恢复夹注、脚注、标题与锚点。现有 MinerU 构建脚本不直接接收看典 JSON。

看典的官方图像 API 提供 `det_mode=sp`、v2 版面、坐标及候选字，竖排结果按右至左、列内上至下排序；其旧 PDF 任务接口已停用，接入时须使用逐页图像接口，不能照旧教程提交 PDF。来源：[看典官方 API 文档](https://kandianguji.com/api_documentation)。具体客户端与调用见 [kandian.md](kandian.md)。

## 当前证据

2026-10-25 一页合成竖排样例：MinerU v4 请求 `vlm` / OCR 开启，返回结构版本 3.4.4，出现漏栏和块合并，部分文字及标点可识别。样例字距较大、夹注是独立同字号栏，不代表真实现代点校本；不能据此声称所有竖排均失败，也不能据此承诺可靠恢复。追加一页密排正文与双行小字夹注的合成样例，同端点/版本误判为表格，正文混栏缺漏、夹注未识别；个别整栏仍可正确识别。两页均为合成输入，尚未测试真实出版物，不能外推所有竖排的准确率。
