# 首次安装与使用引导

用户说「安装并引导使用」或要求首次介绍时，一次发完以下内容；结尾告诉用户「哪一步想具体了解，可以直接追问」。引导说明不逐步等确认；实际处理前的文字层与核对范围选择仍须等用户答复，不先替用户省去 PaddleOCR 或 Obsidian。根据已知环境补上真实路径和当前配置状态，不复述整份内部流程。

## 1. 先说明拿到什么、谁负责什么

把论文、专著、教材或现代排版古籍 PDF 的路径/文件交给 AI，说「把这份 PDF 整理成可在 Obsidian 对照阅读的 Markdown」。AI 默认调用 MinerU 与 PaddleOCR 云端 API，负责参数、正文与脚注结构、标题、逐页对应、交叉核对与整理检查。有原文字层时，先交互询问是否沿用，推荐不沿用并由 MinerU 重新识别重构，不预判文字层质量。预检发现明确编码异常可一并提示，但没有异常不代表可靠。只有用户明确要求评估旧文字层时，AI 才抽取代表页对照原图，不将质量评估设为每次导入的前置步骤，不增加模型依赖。此后用户只处理未决疑字，在读书时发现错漏；AI 如果不能按已定来源、整理或核对流程完成，须交互说明偏差及影响、取得明确许可后才改方案，不能事后仅以“试稿”交付；每份 PDF 处理前让用户选择“仅核双家冲突（推荐）／全书逐页逐字核对”，说明前者只看冲突区域、可能遗漏双家共同错误，后者 AI 额外逐页逐字看图、消耗更高；不得自行扩大范围。AI 自动比较和裁决，仅把未决疑字交用户。不要要求用户运行脚本或选择内部 OCR 技术参数。账号登录、验证码与本机窗口中的令牌输入由本人完成。

首次介绍要同时用 [ocr-support.md](ocr-support.md) 分别说明两家的官方版面能力，不能只说「适合横排，竖排试样页」。用一小段即可：MinerU 云 API 声明支持多栏、文本、表格、公式、图片和图表；PaddleOCR-VL 支持文本、表格、公式和图表，其版面组件还包含标题、目录、脚注、页眉页脚、侧栏与竖排文本类别。给出官方来源链接，并说明这是官方能力范围，现代竖排的列序、标点与双行夹注由 AI 按实际云端样页核验。

## 2. 看插件效果，推荐用 Obsidian 读成品

**PDF Sync Markdown 是本 skill 作者自行开发的配套 Obsidian 插件**，用于把整理后的 Markdown 与 PDF 左右对照、按页联动，并支持校读修订。首次介绍插件时明确说明这层关系，不只说「推荐的插件」。作者推荐用 [Obsidian](https://obsidian.md/download) 搭配它阅读成品；Obsidian 是独立的软件，插件才是作者自制的。先给 [效果预览](https://pdf2md.1012.wiki/demo/)：可以试翻页、左右对照、选字高亮和搜索。**这是预置样例的效果演示，不能拿来上传、阅读或保存自己的书，也不能代替安装插件。** 仓库另有本机网页工作台，只有用户明确询问这种用法时再介绍，不用它替代推荐流程。

在同一条完整引导中问「你已经安装 Obsidian 了吗？准备使用哪个库？」并同时说明已安装/未安装的下一步：未装从官网下载并安装，打开后创建库或把已有文件夹作为库；已有库就沿用，不覆盖现有笔记和设置。确认实际库路径后由 AI 安装配套插件；涉及系统安装或修改已有库，按用户授权执行，不把一个问题拆成多轮步骤确认。

插件尚未安装时：AI 从 [Releases](https://github.com/1012-web/AIhistory1012/releases) 获取 `main.js`、`manifest.json`、`styles.css`，放进 `<库>/.obsidian/plugins/aihistory-pdf-sync/`，合并登记已有第三方插件列表；让用户在 Obsidian「设置 → 第三方插件」信任此库并启用 **PDF Sync Markdown**。新库可用仓库 `install.py --make-vault <路径>`；不对已有非空库直接加 `--force`。无法自动操作时才给对应的手动步骤。

## 3. 两家云端 API 都配置

按 [get-token.md](get-token.md) 由 AI 打开统一的本机配置窗口，一次说明两家官网入口、复制粘贴、保存与分别验证的操作；用户无需手抄命令。窗口缺少图形支持时，才介绍原终端隐藏输入方式。**明确告诉用户：调用 API 不需要安装 MinerU 客户端、PaddleOCR 软件、飞桨框架或本地 OCR 模型，也不需要显卡/CUDA。** 本机只需运行 skill 的 Python 与脚本依赖，由 AI 负责配置；Obsidian 与作者自制插件用于后续阅读和修订，不是调用 OCR API 的前置条件。PDF 会发送给这两家服务，说明隐私与账号计费；不代用户登录、实名、购买额度，不让用户把令牌发到对话里。

AI 验证配置和连接，再进入识别。缺第二家就帮助补配，不能为了演示成功改成默认单家。安装/介绍本身不上传用户材料；用户授权处理具体材料并了解云端去向后，正常调用无需每一步再次确认。

## 4. 教会阅读 Markdown 和修订

- 把整份成品书文件夹放到库中，保留 PDF、正文和配套文件的相对位置；先开书名索引，再点正文。
- Markdown 是可编辑的纯文本：`#` 表示标题，`>` 表示引文，`[^1]` 连接脚注。Obsidian 的阅读视图适合读书，实时预览适合边读边改，源码模式可看到标记。不要删改文件开头的 `pdf` 属性或 `<!--pdf-page.N-->` 页码标记。
- 插件让 PDF 与正文左右对照、按页跟随；在正文选字可在 PDF 定位。疑字清单的链接可跳到对应原页。
- **自己改**：在正文的实时预览/编辑视图直接改错字并保存。一般改字不必重新绑定；若文件与 PDF 失去对应、换了 PDF 或自行整理了笔记，打开笔记，在工具条 **「⋯ → 配对：…（点击改绑）」** 选择 PDF，核对要关联的笔记清单并确认。配对只更新关联，不会把 Markdown 的改字写回 PDF 的文字层。
- **交 AI 改**：漏段、脚注或表格错位时，用插件「复制本页修订请求」，粘给 AI；AI 按原页修订。用户自行修改和 AI 修订都是正常用法。

## 5. 给一个可以直接说的请求

> 把这份 PDF 整理好，放进我的 Obsidian 库：〔PDF 路径〕。拿不准的疑字列出来给我判断。

若安装到用户指定的自定义目录，给出「先读取 `<实际安装目录>/book2md1012/SKILL.md`，再处理这份 PDF」的可用请求；不宣称该目录会在下一轮自动加载。

本地预检是 AI 的内部步骤，不要求普通用户先学会「只预检、不上传」。未给 PDF 的首次安装到完成引导为止，不编造已识别或已完成插件安装。
