# 抽检与通读

先读 [verification-modes.md](verification-modes.md)。导入任务选择仅核双家冲突时，不能自动启动本节的抽页或通读。用户另行要求抽检/通读时，先确认这份文献的具体页范围；已有明确选择按其范围执行，不用“必要检查”扩大看图。

本节用于用户单独要求检查、抽检或通读时。新导入的必要核对和修复仍由主流程完成，不套用这里的“只查不改”。用户已明确要求检查并修复时，可在授权范围内连续完成，采用修订流程的备份、守卫与校注。

目的：告诉用户这份 Markdown 可信到什么程度、问题集中在哪，并给出可以逐条执行的修改清单。**单独检查委托只查不改**；改正文要等用户点头，再按修订模式的做法逐页改。

脚本：`python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/audit_scan.py <子命令> …`（下文简写 `audit_scan`）。`${CLAUDE_SKILL_DIR}` 指主入口 SKILL.md 所在的 book2md1012 目录：Claude Code 会自动替换；在 Codex 等别的平台上没被替换时，自己代入主入口 SKILL.md 所在目录的绝对路径（references 里的命令同理）。
取某页正文用 fix 的工具：`python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/page_tool.py extract "<书>" --page N --numbered`。
参考文件：`references/issue-taxonomy.md`（问题分类）、`references/subagent-prompts.md`（审读提示词）、`references/report-format.md`（输出格式）。

`<书>` 是书文件夹，或单个 `.md`。正文应带 `<!--pdf-page.N-->` 物理页锚点（约定见 `${CLAUDE_SKILL_DIR}/references/anchors.md`）。只有 `<!--p.M-->` 的旧成品：`_数据/book.json` 有 `printedPageOffset` 时脚本按「物理页 = 印刷页 + 偏移」换算照常跑（报告里注明「旧格式」，旧锚点常放在段首而非接缝处，按页的检查会有偏差）；没有偏移就告诉用户先用插件的「补页码锚点」补上，本 skill 不补。

## 分工：脚本做机械活，判断归你

- 脚本（`audit_scan.py`）只做确定的机械活：按规则数字数、查锚点与脚注对应、找残留标签和页眉、出页图、比对事实清单；它报的每条都是「疑点」，严重度只是排序用的提示。遇到异常只报告，从不改正文。
- 内容上的判断由你（对话里的 AI）做：脚本的输出是证据，不是结论。每一处要不要改、改成什么，都对照原页图决定，并向用户说明理由；拿不准就问用户。
- 不为少见情况去改脚本、加自动修补规则；遇到脚本没覆盖的情况，人工处理并在报告里写明。
- **只检查的委托**：报告分「建议改」和「需用户定」两栏，未获修订授权不动正文。已授权检查并修复时，核实明确错误后直接修复；仍未辨明的疑字留给用户。

## 一、零花费初筛（每次都先做）

```bash
python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/audit_scan.py scan "<书>"
```

不调 AI、不调接口，几秒钟。写出 `<书>/_数据/过程报告/抽检初筛.md` 与 `.json`（`--out-dir` 可改位置；没有 `_数据` 时会新建）。查的项：

| 项 | 怎么查 |
|---|---|
| 锚点缺页、重复、倒序、超出 PDF 页数、写法不规范 | 全书按文件次序串起来看 |
| 锚点错位 | 锚点后头 12 个字应在文字层本页开头；出现在上一页或下一页就是放早、放晚了 |
| 每页字数 | 本页正文 + 挂在本页的注，对比文字层（去掉页眉页脚）；没有文字层时对比全书每页中位数 |
| 脚注 | 注码无注文、注文无注码、重复定义、注号跳号、次序倒置、注文挂页与注码所在页不同、注文缺页锚点；注文续到下一页而没标续页锚点（提示可补，可选） |
| 标题 | 层级跳级；「一、二、四」「第一章、第三章」「2.1、2.3」这类编号跳号 |
| 残留标签 | HTML 标签、非锚点注释、`$^{1}$` 之类 LaTeX、模型特殊记号、版面块类型名、HTML 实体 |
| 长段拉丁文 | 80 字以上的拉丁字母串（英文摘要标为「提示」） |
| 知网等水印、页眉页脚 | 水印固定词；从文字层认出各页反复出现的页眉页脚，再到正文里找；孤立页码行、刊期行 |
| 上标并入 | 正文的数字串文字层没有、去掉末一两位却有（「10¹」→「101」）；无文字层时只做弱猜测 |
| 括号引号不成对 | 逐段数（）()【】[]《》〈〉“”‘’「」『』 |
| 重复串 | 整段重复、段内同一串连写两遍、相邻页两段有 20 字以上相同 |
| 导入时报过的表格页 | 读导入留下的报告：`_数据/冲突清单/conflicts.json`（没有就读 `冲突清单.md`）里「表格个数」对不上的页（条目形如「表格 · 表格个数：MinerU 0，VL 1」）；`_数据/过程报告/_build_report.txt`「疑似跨页表」一节、`_数据/文字层/assignment.json` 的 `crossPageTables` 里的页。都报「中」，因而进必查页 |

把初筛结果用几句话告诉用户：高、中疑点各几条，集中在哪几页，最要紧的是什么。

初筛的局限要说清：它只查得出「机器能查的」。整段漏掉但字数刚好被别的错误抵消、错字、标题层级用错、表格行列错，都要靠看图。没有文字层（扫描件、且没有 `.文字层.pdf` 副本）时，字数只能和中位数比，接缝与上标两项基本失效。

## 二、决定读多少

问用户要哪一档（只给建议，不替用户定）：

1. **只看初筛**：零花费，到此为止。
2. **抽检**（推荐）：读初筛给的建议抽查页（`suggested_pages`）。
3. **全书通读**：每页都读。

**抽页**（`scan` 已按此给出，可用 `--sample N` 改样本量、`--seed` 改随机种子）：

- 必查页：初筛有中、高疑点的页，全部进第二步高清通读。**导入时表格个数两家不同的页、疑似跨页表的页一定在内**（脚本从导入报告里读出来，见上表最后一行）：表格行列错、续表并错页，字数和接缝核对都查不出；书文件夹里没有这些导入报告（比如不是 book2md1012 导入的）就没有这一类，要在报告里说明；
- 结构页：目录、章首、表格页、图片页、注多的页，最多占样本一半；
- 随机页：其余页里随机补足样本。

**三分之一法则**（报告里必须写明）：随机抽 n 页全对，只能说明其余页的错误页比例大约 < 3/n（95% 把握）。抽 30 页全对约 < 10%，抽 100 页全对约 < 3%。它说明不了「没有错」；必查页、结构页是挑出来的，不算随机样本，不能拿来算这个比例。

**花费**：抽检和通读都要派子代理看图，**开工前先报花费、等用户同意**。要读的页数 = 必查页 + 结构页 + 随机页（必查页不占 `--sample` 的名额，另外加）。

估算按页算。单步估算（下表）只算一次输入输出，不含子代理多轮、重试和 `effort high` 的思考，实测远高于它：

- 论文 12 页通读，实测约 **37 万 token**，约每页 3 万；
- 专著抽检，实测约 **74 万 token**；事先按下表单步估算的只有 8–9 万。

所以报价按「要读的页数 × 约 3 万 token/页」算，或按用户自己的实测；下表只用来看各步占多少，不用来报总数。只报 token 数，折合多少钱或额度取决于套餐，说明这一点。

| 步骤 | 每页约（单步） | 说明 |
|---|---|---|
| 低清列事实（60 dpi） | 0.6 千 token | 每批 10 页另加约 1 千 |
| 高清通读（150 dpi + 本页正文） | 5 千 token | 每批 3～5 页另加约 3 千 |

例：读 25 页（必查 + 结构 + 随机）约 75 万 token；900 页全书通读约 2700 万 token，通常不现实，先和用户确认范围。把实际页数代进去算，说明是估计。

## 三、AI 两步法（抽检）

子代理一律用 Agent 工具、`effort: "high"`；可并行派多批。提示词照 `references/subagent-prompts.md`。

1. **出低清图**：

   ```bash
   python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/audit_scan.py render "<书>" --pages 3,5-7,12 --dpi 60 --out-dir "<草稿目录>/low"
   ```

   图放会话草稿目录（scratchpad），不放书文件夹或库里。

2. **列事实清单**（模板 A）：子代理只看图、不看正文，每页给出段落数、注码数、注文条数、标题、表格、图、首尾各 10 字。汇总成 `<书>/_数据/过程报告/抽检-事实清单.json`。

3. **程序比对**：

   ```bash
   python -X utf8 ${CLAUDE_SKILL_DIR}/scripts/audit_scan.py compare "<书>" --facts "<书>/_数据/过程报告/抽检-事实清单.json" --out "<书>/_数据/过程报告/抽检-比对.json"
   ```

   有对不上的页时退出码是 1，这是正常结果，不是出错。想先看正文这边的事实：`audit_scan facts "<书>" --pages 3,5-7`。

4. **高清通读对不上的页**（模板 B）：`verdict` 为「需高清通读」的页、子代理标了 `unsure` 的页、初筛有中高疑点的页（即必查页），出 150 dpi 图（`render --dpi 150`），连同 `page_tool extract` 的本页正文和该页初筛疑点交给子代理。子代理逐页回 `no_issues` 或 `issues`，并对每条初筛疑点给「确有其事 / 误报」。

5. 事实清单与正文一致、初筛也没疑点的页，算「无问题」，不再高清读。这是省钱的关键；要更稳，可以对随机页也做第 4 步（花费照第二步算）。

**全书通读**：不分两步，每批 3～5 页直接用模板 B；分轮派，每轮汇总后再派下一轮。

主代理自己也可以抽一两页亲自看图复核子代理的结论，尤其是高严重度、低把握的条目。

## 四、输出

按 `references/report-format.md`：

- 机器读：`<书>/_数据/过程报告/抽检-审读.json`，逐页 `no_issues` / `issues`；每条问题带类型（OmniDocBench 块类型 + 错误种类，见 `references/issue-taxonomy.md`）、严重度、页图证据、正文定位片段、建议改法、把握。
- 人读：`<书>/_数据/过程报告/抽检报告-<日期>.md`：结论（读了几页、错了几页、三分之一法则的上限）、问题清单（编号 `p<页>-<序>`）、初筛误报、没读到的页、下一步。

给用户的回复：结论几句话 + 高严重度问题列表 + 报告路径 + 问用户要改哪些。

## 五、改正文（用户同意后）

- 用户已授权“检查并修复”，或对报告回复「改 p7-1、p9-2」「全部按建议改」后，在相应范围内动正文。
- 按修订模式的做法逐页改（`${CLAUDE_SKILL_DIR}/references/revision.md`）：每页先 `snapshot`，只动本页、锚点不动，改字记校注，改完 `guard`。
- 涉及挪锚点（锚点错位、注文挂错页）的，照 fix 的「四之二、锚点放错」：停下、给建议、用户同意才挪。
- 改完对改过的文件重跑一次 `audit_scan scan`，把前后疑点数报给用户。

## 注意

- 原件是唯一依据：文字层、MinerU、PaddleOCR 都可能错。原书误印照录，报成 `info`，不算错误。
- **几家识别犯同一个错时，冲突清单和初筛都抓不到。** 真实案例里，一张表中的一个生僻字被四家 OCR 认成同一个形近的常用字；云端 OCR 还会把「痾」认成「病」、「沴」认成「诊」，表里的「—」认成「一」。所以抽检、通读时，专门术语、生僻字、表格里的单字格，要对照原页图逐字核，不能因为几家一致就默认是对的。这是给你的提醒，不是自动替换规则：不要按字表批量改，每处都看图定。
- 只读图、不改写：建议改法只说怎么改回原书的样子，不润色。
- 抽检结论只覆盖读过的页；报告里不要写「全书无误」之类的话。
